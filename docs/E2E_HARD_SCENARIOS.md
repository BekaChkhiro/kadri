## სად პასუხობს AI ზედაპირულად

1. **შაბლონური 5 ნაბიჯი.** round 1 ყველა სცენარში ზუსტად 5 ნაბიჯს აბრუნებს და 10-დან 8 ერთ round-ში იხურება.
   სქემა ერთნაირია: „ვიზუალურად შეამოწმე → გაწმინდე/გაათავისუფლე → მიმართე სპეციალისტს“. ჰიპოთეზების რიგი
   და გამორიცხვის ლოგიკა არ ჩანს („თუ X, მაშინ Y, თუ არა, Z“).
2. **გაზომვას არ ითხოვს.** R4-ში (მულტიმეტრი, mA) და R3-ში (წნევის დინამიკა, ავზი) პასუხი სწორედ გაზომვაზეა
   დამოკიდებული. სქემაში ასეთი გზა არ არსებობს: continuation მხოლოდ `complete | needs_photo`-ია, ტექსტური ან
   რიცხვითი პასუხის მიღება კი არ შეუძლია.
3. **needs_photo იშვიათია.** ფოტოს მხოლოდ მაშინ ითხოვს, როცა შემდეგი ფიზიკური მოქმედება ჩანს (R5, 1b).
   დიაგნოსტიკისთვის არასდროს ითხოვს (R1: უკანა მხარე/საყინული, R3: ავზი/რადიატორი, R4: მულტიმეტრი).
   5 round-ის ლიმიტამდე არცერთი სცენარი არ მისულა, ანუ ლიმიტი პრობლემა არაა, AI თვითონ ჩერდება ძალიან ადრე.
4. **ფოტოს და ტექსტის ფაქტებს არ იყენებს.** R2-ში ავტომატების მარკირება წაიკითხა, მაგრამ ჩამოვარდნილს არ
   ასახელებს. R7-ში ფანჯარას ვერ ხედავს. R6-ში იმეორებს იმას, რაც მომხმარებელმა უკვე სცადა.
5. **„სპეციალისტი“ როგორც ჩიხი.** უსაფრთხოების თვალსაზრისით სწორია (R2, R6, R7: ✅), მაგრამ ხშირად ჩნდება მაშინაც,
   როცა მიზეზის პოვნა უსაფრთხოდ შეიძლებოდა (R3 შევსება, R4 პარაზიტული დენი, R10).

უსაფრთხოება საერთოდ კარგია: ავტომატის გამორთვა სანათთან, „ნომინალი არ გაზარდო“, „სახურავზე ნუ ახვალ“,
„მუშა ძრავზე კლემა არ მოხსნა“, უსაფრთხო დაცლა. სახიფათო რჩევა არცერთ სცენარში არ ყოფილა.

3. **ერთი timeout ან არასწორი პასუხი მთელ სესიას აგდებს (backend/UI).** R5 round 3: `timeout` ფოტოს მიწოდებიდან
   ~47 წმ-ში, ორი წარმატებული round-ის შემდეგ ეკრანი „ვერ გავაგრძელე“ ჩნდება. R9: `ai_invalid_response`.
   გასწორება:
   - Worker-ში ერთი ავტომატური retry: invalid JSON → ხელახალი გენერაცია, timeout → ერთხელ კიდევ.

   - error ეკრანზე ჩანდეს, რომელი round ჩავარდა.
4. **„ობიექტის გარეშე“ ფოტო ვერ მუშავდება (AI სქემა).** R9-ში ცარიელ კედელზე, როცა ამოცანა თავად კედელია (სად
   გავბურღო), parts/steps სქემა ჩავარდა. სათაურად „ფოტო“ დარჩა.
   გასწორება: სქემამ დაუშვას ზედაპირი/ზონა ნაწილად („კედლის მონაკვეთი“, „როზეტის ზონა — არ გაბურღო“) და
   0 ნაწილი + needs_photo/needs_answer. prompt-ში იყოს ცხადი შემთხვევა „ობიექტი არ ჩანს“.
5. **ფოტოს და ტექსტის დეტალები ნაბიჯებში არ ჩანს; focus ბუნდოვანია (AI + UI).**
