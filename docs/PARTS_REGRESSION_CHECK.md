# /ai/parts რეგრესიის შემოწმება (deploy-ის წინ)

**ეს შემოწმება ყოველი Worker deploy-ის წინ მეორდება.** ის ადარებს deploy-ამდე
staging-ზე მყოფ ვერსიას („ძველი“) და ამ checkout-ის კოდს, გაშვებულს ლოკალურად
`wrangler dev --local`-ით guarded route-ებით („ახალი“). ორივე მხარე დარდება
realism-გაშვების `parts.json` რეფერენსსაც. ფასიანია: 6 გამოძახება `/ai/parts`-ზე,
steps არ გამოიძახება.

## გაშვება

```sh
cd backend/worker
export PATH=/opt/homebrew/opt/node@22/bin:$PATH
set -a; source <main checkout>/experiments/som-test/.env; set +a   # OPENAI_API_KEY ლოკალური Worker-ისთვის
node scripts/parts_compare.mjs \
  --realism <main checkout>/experiments/som-test/out_realism/c_astra_tracking
# სურვილისამებრ: --old <staging url> --staging-env ~/.config/kadri/staging.env
#                --new <უკვე გაშვებული ლოკალური url> --port 8798 --cap 0.30 --max-calls 6
```

- ძველი მხარის token-ს სკრიპტი თავად აწერს `--staging-env` ფაილის `SESSION_SECRET`-ით
  (ნაგულისხმევად `~/.config/kadri/staging.env`). ახალი მხარის token-ს აწერს
  `.dev.vars`-ის `SESSION_SECRET`-ით (gitignored). საიდუმლოები და token-ები არ იბეჭდება.
- ფოტოები: `<scene>/<slug>/original/run_1/input.png` → ≤768 px JPEG q88 (`sips`).
  ინსტრუქციები იგივეა, რაც realism-გაშვებაში და live_check.mjs-ში
  (`parts_request/request.json`-ის ნაბიჯების სია). სცენებია sink-trap, car-engine და gym-lat-pulldown.
- ხარჯს `scripts/ledger.json` აღრიცხავს: თითო გამოძახება წინასწარ იჯავშნება $0.10-ით
  და მერე `costUsd`-ით სწორდება. cap $0.30 ამ კონკრეტულ გაშვებას ეხება.
  ახალი Worker-ის შიდა retry `costUsd`-ში არ ჩანს. ამიტომ, როცა wall time
  `latencyMs`-ს 2.5 წმ-ზე მეტით აჭარბებს, ცდა `retried` ნიშანს იღებს და ledger-ში ორმაგად იწერება.
- შედეგი: `backend/worker/scripts/out/parts_compare.json`. სურათები:
  `scripts/out/parts_compare_{sink,car,gym}.png` (რეფერენსი მწვანით, ძველი წითლით, ახალი ლურჯით; ეს ფაილები gitignored-ია).

## შედარება და რეგრესიის კრიტერიუმები

ნაწილები ჯერ ნორმალიზებული label-ის თავით წყვილდება (ტექსტი „—“-მდე, „,“-მდე ან „(“-მდე),
დანარჩენი კი ხარბად, საუკეთესო IoU-თი. საშუალო IoU დაწყვილებულ ნაწილებზე ითვლება.
მოდელი არადეტერმინისტულია, ამიტომ მცირე სხვაობა ნორმაა. **რეგრესიად** ითვლება
ის, რაც ახალ მხარეზე ჩნდება და ძველზე არა, ან ორ მხარეს შორის დიდი სხვაობა:

- ნაწილების რაოდენობა ძველისას ან რეფერენსისას ±3-ზე მეტით სცდება;
- ჩნდება ფონის ტიპის ნაწილი: label-ის სიტყვა იწყება ასე: კედელ/კედლ, იატაკ, ფონ, ზონ, ზედაპირ
  (ან wall/floor/background/zone/area/surface), ან box სურათის 60%-ზე მეტს ფარავს;
- საშუალო IoU რეფერენსთან ან ძველთან < 0.6;
- ახალი მხარე შეცდომას აბრუნებს.
