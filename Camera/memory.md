# Decisions

Decisions agreed on while designing are recorded here.

- 2026-10-17 — აპი: მობილური realtime კამერა + ობიექტების ამოცნობა (bounding box) + AI ასისტენტი ყველა თემაზე (არა მხოლოდ ნავიგაცია). სამუშაო სახელი „კადრი“.
- 2026-10-17 — სტილი: ღია, მინიმალისტური (frosted light glass პანელები კამერაზე, თხელი თეთრი ჩარჩოები, ერთი ლურჯი აქცენტი brand-500 #2F6BFF არჩეული ობიექტისთვის).
- UI ენა ქართული; შრიფტი Inter + Noto Sans Georgian.
- მთავარი ეკრანი (artboards/camera.tsx): ზედა ზოლი (live სტატუსი, ფლეში, პარამეტრები) → ობიექტების ჩარჩოები (შეხებით არჩევა) → ასისტენტის ბარათი პასუხით და სწრაფი კითხვებით → რეჟიმები (ამოცნობა / კითხვა / თარგმნა / ინსტრუქცია) → გალერეა · ხმოვანი კითხვის ღილაკი · ისტორია.
- 2026-10-17 — ფოკუსი გადავიდა პრაქტიკულ სცენარზე: **შეკეთება / აწყობა**. მთავარი ეკრანი artboards/repair.tsx: AR მიზანი (Target), ბრუნვის ისარი (TurnArrow, cw/ccw), კადრს მიღმა ნაწილის მინიშნება (EdgeHint), ნაბიჯების ბარათი (პროგრესი, ხელსაწყოები, შენიშვნა, უკან / შესრულდა, ხმით კითხვა). AR კოორდინატები ფოტოს (2:3) სივრცეშია.
- 2026-10-17 — მეორე პრაქტიკული სცენარი: **სპორტდარბაზი** (artboards/gym.tsx). ტრენაჟორის ამოცნობა + სამი ჩანართი: მომზადება (დანომრილი Marker-ები ნაწილებზე ↔ სია ბარათში), მოძრაობა (MoveArrow: მიმართულება, სეტი/გამეორება/დასვენება), შეცდომები (danger მარკერები). კამერის კადრი იწყება ზედა ზოლის ქვემოდან (header ღია ზოლზე), რომ ზედა ნაწილები არ დაიფაროს.
- 2026-10-17 — **Realtime tracking**: მონიშვნები ობიექტზე უნდა „ეკროს“, როცა კამერა მოძრაობს. design-system-ში TrackedFeed: ფოტო + AR ერთ ფენაში, ხელის რხევის სიმულაცია (10s loop) + თითით გადათრევა; reduced-motion → რხევა გამორთულია, თრევა რჩება. გამოყენებულია gym და repair ეკრანებზე. რეალურ აპში: ARKit / ARCore anchors.
- 2026-10-17 — **ბადისებრი გარსი (MeshWrap)**: ობიექტს ფორმაზე მორგებული wireframe ბადე ეკვრის (სამკუთხა ბადე + ღია ლურჯი შევსება + მანათობელი თეთრი კონტური). ამოცნობისას სკანის ხაზი ზემოდან ქვემოთ ჩადის და ბადეს „აკრავს“ (~1.3s), კონტური იხატება. TrackedFeed-ის შიგნითაა, ამიტომ კამერასთან ერთად მოძრაობს. ფორმები ფოტოს პიქსელებში. gym: ტრენაჟორი ნაწილებად; repair: სიფონი.
- 2026-10-17 — **სკანი → ფოკუსი ნაბიჯებით**: ჯერ მთელი ობიექტი სკანირდება (ყველა ნაწილზე ბადე), შემდეგ თითოეულ ნაბიჯზე მხოლოდ საჭირო ნაწილები ნათდება (MeshWrap `focus`): მკვეთრი შევსება + სქელი მანათობელი კონტური, დანარჩენი ქრება 15%-მდე, კადრი ირგვლივ ბნელდება (spotlight). მარკერები/ისრები მხოლოდ სკანის შემდეგ ჩნდება. TrackedFeed `pan`: კამერა ავტომატურად იხრება, რომ ფოკუსი ბარათის ზემოთ მოექცეს. gym ახლა ნაბიჯებიანია (5 ნაბიჯი) repair-ის მსგავსად.
- 2026-10-17 — მესამე მაგალითი: **მანქანა / ზეთის შემოწმება** (artboards/car.tsx). MeshWrap `avoid`: ნაწილები წითლად („არა ეს“), danger მარკერები ✕. ბარათში ზეთის დონის ილუსტრაცია (MIN–MAX).
- მოძრაობა: ჩარჩოები spring-ით ჩნდება (60ms stagger), პასუხი იცვლება 200ms fade/slide, ბარათი 300ms easeOut; reduced-motion → მხოლოდ opacity, live წერტილის pulse გამორთულია.
