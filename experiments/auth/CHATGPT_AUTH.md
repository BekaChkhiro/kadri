# „კადრი“ — ChatGPT ავტორიზაცია და მომხმარებლის დაფინანსებული AI

შემოწმებულია **2026-10-17**; საჯარო ოფიციალური წყაროების კვლევა. API, რეგისტრაცია, ავტორიზაცია და არაოფიციალური მეთოდების ტესტირება: **0**. შეფასების კონტექსტია [Camera/brief.md](../../Camera/brief.md) — iOS/Android კამერა, ობიექტების მონიშვნა და AR ინსტრუქციები.

**პასუხი: ოფიციალური გზა უკვე არსებობს, მაგრამ „კადრისთვის“ ავტომატურად ხელმისაწვდომი არ არის.** `Sign in with ChatGPT` ერთმანეთისგან გამოყოფს იდენტობასა და გეგმის გამოყენების ნებართვას. კომერციული პარტნიორები შეზღუდული პროგრამით ერთვებიან; საჯარო ინსტრუქცია open-source/local აპებისთვისაა. ფასიანი ან remotely hosted აპისთვის მითითებულია ინტერესის ფორმა. „ყველა ChatGPT subscription API-დ გამოდგება“ მცდარია; „ასეთი მექანიზმი საერთოდ არ არსებობს“ — ასევე. [Quickstart](https://developers.openai.com/siwc/quickstart), [მოქმედების ფარგლები](https://developers.openai.com/siwc/token-sharing-open-source).

**SIWC-ის ზუსტი კონტრაქტი:** `POST https://api.openai.com/v1/responses`, OAuth bearer token, `store:false`, `stream:true`. მოდელები ანგარიშის `GET /v1/models` კატალოგიდან აირჩევა; დოკუმენტაციის მაგალითი `gpt-6.1-sol`-ს იყენებს და Astra-ს ყველა ანგარიშისთვის არ ჰპირდება. `gpt-6-astra` ამ გზაზე კონკრეტული მომხმარებლისთვის **დაუდასტურებელია**. ეს ორი endpoint მხოლოდ დოკუმენტაციაში წავიკითხეთ, არ გამოგვიძახებია. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

**Vision და Realtime:** SIWC იღებს ტექსტს, სურათებსა და ფაილებს, თუ მოდელი მათ იღებს; არ უჭერს მხარს audio/video input-ს, Files upload API-ს, transcription-სა და image-generation tool-ს. დოკუმენტირებული inference გზა Responses-ია; `/v1/realtime`-ზე ამ ნებართვის გავრცელება არ შეიძლება. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [route restrictions](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

ჩვეულებრივ API-ში **Astra: text/image → text**, Responses/Chat Completions მხარდაჭერით; თავად Astra **არ უჭერს მხარს Realtime-ს, აუდიოსა და ვიდეოს**. კადრის JPEG-ად გაგზავნა vision-ია და არა უწყვეტი ვიდეოს დამუშავება. Realtime ცალკე მოდელით, მაგალითად `gpt-realtime-2.1`, და ცალკე API ბილინგით უნდა დაიგეგმოს; mobile კლიენტისთვის სერვერი მოკლევადიან credential-ს გასცემს. [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Realtime](https://developers.openai.com/api/docs/guides/realtime).

## 3. წესები და არაოფიციალური გზები

მომხმარებლის subscription-ის გამოყენება **დასაშვებია დოკუმენტირებული SIWC თანხმობისა და შესაბამისი დაშვების ფარგლებში**. ეს არ ნიშნავს browser session/cookie-ის ან Codex-ის შენახული token-ის შეგროვებისა და საერთო proxy backend-ად გადაკეთების ნებართვას. Terms კრძალავს credential-ის გაზიარებას, არანებადართულ ავტომატურ extraction-ს, reverse engineering-სა და ლიმიტების გვერდის ავლას; დარღვევას შეიძლება მოჰყვეს შეჩერება/ანგარიშის გაუქმება. [Terms — საქართველოსთვის შესაბამისი non-EEA ვერსია](https://openai.com/policies/row-terms-of-use/).

Codex დოკუმენტაცია საკუთარ headless გარემოში credential-ის გადატანას აღწერს, ამიტომ **ყოველი token reuse აკრძალულია** ზედმეტად ფართო დასკვნა იქნებოდა. მაგრამ ეს „კადრის“ მომხმარებლების session-ების შეგროვების ან დაუდასტურებელი endpoint-ების გამოყენების უფლებას არ ადგენს; ოფიციალური SIWC პირდაპირ ითხოვს საკუთარ token record-ს და public Responses-ს, არა `backend-api`-ს. რისკის შეფასება: ანგარიშის კომპრომეტაცია, refresh/revocation-ზე მოულოდნელი გათიშვა, უცნობი ბილინგი და არასტაბილური პროტოკოლი. [Codex auth](https://developers.openai.com/codex/auth), [SIWC sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [endpoint](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

BYOK-საც სჭირდება დაცვა: საერთო developer key აპში არ ჩაიდოს; მომხმარებლის key არ გავაზიაროთ სხვა მომხმარებლებთან და არ შევიტანოთ ლოგებში. ცენტრალიზებული key custody-ის კომერციული პირობები ცალკე დასაზუსტებელია; ყველაზე მკაფიო კონტროლი მომხმარებლის საკუთარ backend/proxy-ს აქვს. ეს უსაფრთხოების რეკომენდაციაა, არა store approval-ის გარანტია. [API key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety).

- **ჩვენი subscription/IAP:** ჩვენ ვიხდით API-ს, მომხმარებელი ყიდულობს მკაფიო სესიის ლიმიტს/კრედიტებს. ეს ჩვენი რეკომენდებული ბიზნესმოდელია და არა არსებული ინტეგრაცია. API-ს ბილინგი დამოუკიდებელია; store-ის ციფრული მომსახურების წესები ვრცელდება. [API billing](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform), [Apple §3.1](https://developer.apple.com/app-store/review/guidelines/#payments), [Google Payments](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en).

**App Store:** ციფრული ფუნქციის ფასიანად გახსნა ჩვეულებრივ IAP-ს მოითხოვს. აშშ storefront-ში გარე გადახდის ბმულებს სპეციალური გამონაკლისი აქვს; სხვა რეგიონებში entitlement/შესაბამისი პირობებია. BYOK ან ChatGPT login ავტომატური გამონაკლისი არ არის — „კადრის“ დამტკიცება **დაუდასტურებელია**. მესამე მხარის login-ით ძირითადი ანგარიშის შექმნისას §4.8-ის ეკვივალენტური privacy-preserving login მოთხოვნაც შესამოწმებელია. **Play:** ძირითადი წესი Play Billing-ია; ალტერნატიული billing/გარე ბმულები მხოლოდ შესაბამის რეგიონულ პროგრამებში ჩართვით. კამერის სცენარში ფიზიკურ ნივთზე რჩევა თავისით AI სერვისს ფიზიკური საქონლის გადახდად არ აქცევს — ეს ჩვენი შეფასებაა. [Apple §§3.1, 4.8](https://developer.apple.com/app-store/review/guidelines/), [Play §§2, 4, 8–9](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en).

## 5. ეკონომიკა, UX და რეკომენდაცია

მოთხოვნაში მოცემული **1–3 vision მოთხოვნა და $0.05–0.10/ცდა** აქ დაგეგმვის დაშვებაა: მიმდინარე [REALISM.md](../som-test/REALISM.md#ხარჯი-და-გაჩერების-მიზეზი) ინდივიდუალური სესიის ამ დიაპაზონს არ ამტკიცებს და ledger-ის შეფასებას ინვოისისგან არჩევს. ამ დაშვებით 100 სესია = **$5–10**, 1,000 = **$50–100** მხოლოდ მოდელისთვის; თუ თანხა თითო მოთხოვნას გულისხმობს, 1–3 მოთხოვნაზე სესია **$0.05–0.30** გამოდის. არ ვამრავლებთ ცდის ფასს ხელახლა, სანამ ერთეული არ დაზუსტდება. Astra-ს საჯარო მოკლე-context Standard ტარიფია $10/M input და $50/M output tokens; SIWC-ის allowance-ის API დოლარებში ზუსტი ეკვივალენტი **დაუდასტურებელია**. [ტარიფი](https://developers.openai.com/api/docs/models/gpt-6-astra).

**~7 წამი სრული სესია არ არის:** C stress/tracking-ის first-box p50 არის 6.78/7.49 წმ; პირველი step — 14.50/17.14 წმ; სრული ცდა — 27.48/30.59 წმ. ეს მცირე, სინთეზური desktop გაზომვებია, არა mobile SLA. ავტორიზაციის შეცვლა ამ დროს თავისთავად ვერ შეამცირებს; SIWC latency არ გაზომილა. [ადგილობრივი მტკიცებულება, ხაზები 88–105](../som-test/REALISM.md#დრო-p50--p90--n).

UX შეფასება: კამერამდე სავალდებულო login ფართო აუდიტორიას დამატებით ნაბიჯს აძლევს. პარტნიორული დაშვების შემთხვევაში არჩევითი „გამოიყენე შენი ChatGPT გეგმა“ onboarding/settings-ში სჯობს; უნდა ჩანდეს აქტიური დაფინანსება და limit/reconnect მდგომარეობა. საჯარო OSS flow იყენებს system browser + PKCE-ს და `127.0.0.1` loopback callback-ს; native universal/app links და მზა iOS/Android SDK ამ წყაროში **დაუდასტურებელია**. კომერციული mobile callback უნდა შეთანხმდეს OpenAI-სთან. [Sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [UX მოთხოვნები](https://developers.openai.com/siwc/ui-ux-guidelines).

**რეკომენდაცია:** „კადრის“ გაშვება დავგეგმოთ ჩვენი API backend + შეზღუდული საცდელი სესიებით + IAP-ით. SIWC განვიხილოთ არჩევით ხარჯის გადატანის გზად მხოლოდ კომერციული/native დაშვების, Astra vision entitlement-ისა და store flow-ის დადასტურების შემდეგ; Free მომხმარებელზე მას ნუ დავეყრდნობით. OpenAI-ს შემდეგ ეტაპზე დასასმელი საკითხებია mobile/hosted eligibility, მოდელები/კვოტა, billing და callback; ამ კვლევაში ფორმა არ გაგვიგზავნია. [პროგრამის ფარგლები](https://developers.openai.com/siwc/token-sharing-open-source). Apps SDK — companion არხი; BYOK — დამატებითი ტექნიკური რეჟიმი; reverse-engineered session — არ გამოვიყენოთ.
