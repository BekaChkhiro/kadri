## ვიზუალური შემოწმება — API-მდე, 2026-10-17

სამივე `marked.png` და ცალკეული მასკების `parts.png` რეალურად დათვალიერებულია. საბოლოო შედეგი მიღებულია SAM2.1_b-ით, MPS-ზე (Apple M5), 32×32 grid და ერთი crop-ფენით. Crop-ების გარეშე დარჩა 11/14/13 მასკა (sink/gym/car; 19.4/9.7/8.2 წმ); crop-ფენით — 11/16/19 (18.6/17.9/16.8 წმ). ეს ერთჯერადი გაზომვებია და არა benchmark; პირველი გაშვების გახურების ეფექტიც მოქმედებს.

- **სიფონი:** `p10` ცალკე გამოყოფს მარჯვენა ქანჩს; `p7` თითქმის მთელ მილების სისტემას აერთიანებს. `p5` ფოტოს მარცხენა ონკანს შლანგთან ერთად მოიცავს. ფოტოს უფრო მარჯვნივ მდებარე მეორე ონკანს დამოუკიდებელი მასკა არ აქვს. `p4`/`p6` ზედა შეერთებების ცალკე მასკებია; გარსები ნაწილობრივ ჩადგმულია `p7`-ში. შუასადები შიგნითაა და ფოტოზე არ ჩანს. მხოლოდ ეს სურათი მის ზომას/მდგომარეობას ვერ ამტკიცებს.
- **ჯიმი:** სახელური `p3`, ბალიშები `p10`/`p11`, სავარძელი `p15` გამოსადეგად გამოიყო. წონების ბლოკი, ქინძისთავი, კაბელი და სავარძლის ყვითელი რეგულატორი დამოუკიდებელ მასკებად არ გამოიყო. Crop-ფენამ ძირითადად ფონის ნაწილები დაამატა. ამ ნაწილების ნაცვლად ფონზე არსებული ID-ის მითითება მცდარი პასუხი იქნება.
- **მანქანა:** ზეთის ხუფი `p6`, ძრავის საფარი `p8`, ანტიფრიზის ავზი `p4`/ხუფი `p3`, მინის სითხის ავზი `p13`/ხუფი `p11` გამოიყო. ზეთის საზომის ყვითელი რგოლი კვლავ დამოუკიდებელი მასკის გარეშეა. `p5` მხოლოდ აკუმულატორის წითელი ტერმინალის საფარია, არა მთელი აკუმულატორი. რამდენიმე სხვა მცირე დეტალი crop-ფენამ დაამატა, მაგრამ მთავარი გამოტოვება ვერ გამოასწორა.

**შუალედური დასკვნა:** ტექნიკური ჯაჭვი „მასკა → სტაბილური ID შენახულ ფოტოზე → დანომრილი ფოტო“ მუშაობს. არჩეული SAM2 automatic პარამეტრები ყველა საჭირო სემანტიკურ ნაწილს ვერ გამოყოფს; ეს უკვე ზღუდავს მომავალ ID-არჩევას, OpenAI-ის პასუხის ხარისხისგან დამოუკიდებლად. ზოგად უნივერსალურ გამოყენებაზე დადებითი დასკვნა ჯერ არ გვაქვს.

**რეკომენდაცია:** API ცდებში აუცილებლად აღირიცხოს unknown_parts და ცარიელი focus იქ, სადაც ნაწილი არ არის სეგმენტირებული. მომავალ ცალკე შედარებაში შეამოწმეთ უფრო ხშირი grid, სამიზნე crop ან point-prompted გადაჭრა პატარა ნაწილებისთვის. არსებული მასკების ხელით „გასწორება“ ამ ექსპერიმენტის შედეგში არ გაკეთებულა. FastSAM არ გამოყენებულა — offline SAM2 საკმარისად სწრაფია, პრობლემა ნაწილების დაფარვაა.

ჯერ არ შეფასებულა OpenAI-ის ID-არჩევა, სამი პასუხის თანმიმდევრულობა, API latency ან რეალური ტოკენები/ფასი. ამ მონაცემების ნაცვლად სინთეზური პასუხები არ ჩაგვინაცვლებია.
